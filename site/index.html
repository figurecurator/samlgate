브라우저 로그인으로
AWS CLI 시작하기. AWS credentials from
a browser sign-in.

평소처럼 브라우저에서 조직 계정(Microsoft Entra ID, Okta, Google Workspace 등)으로 로그인하면, samlgate가 SAML 응답을 받아 AWS STS 임시 자격 증명으로 바꾸고 ~/.aws/credentials에 저장합니다. saml2aws login을 그대로 대체합니다. Sign in to your IdP (Microsoft Entra ID, Okta, Google Workspace, …) in a real browser. samlgate catches the SAML assertion, exchanges it with AWS STS for temporary credentials and writes them to ~/.aws/credentials — a drop-in replacement for saml2aws login.

직접 설치하기Install it yourself

Windows

관리자 PowerShell에서 Chocolatey로 설치합니다.Install with Chocolatey from an elevated PowerShell.

choco install samlgate -y
samlgate --version

x64·ARM64 ZIP은 릴리스에서 받을 수 있습니다. Microsoft Edge(기본 설치) 또는 Chrome·Brave·Chromium·Whale이 필요합니다.x64 and ARM64 ZIPs are on the releases page. Needs Microsoft Edge (preinstalled) or Chrome, Brave, Chromium or Whale.

macOS (Apple Silicon)

Homebrew로 설치합니다.Install with Homebrew.

brew install figurecurator/tap/samlgate
samlgate --version

Microsoft Edge 또는 Chrome(혹은 Brave·Chromium·Whale)이 필요합니다. Intel Mac은 소스 빌드만 가능합니다.Needs Microsoft Edge or Chrome (or Brave, Chromium, Whale). Intel Macs: build from source.

처음 쓰기Quick start

# 1. IdP 로그인 URL 저장 (saml2aws를 쓰고 있었다면 생략)1. Save your IdP sign-in URL (skip if you already use saml2aws)
samlgate configure --url "https://launcher.myapps.microsoft.com/api/signin/<app-id>?tenantId=<tenant-id>"

# 2. 로그인 — ~/.aws/credentials의 [saml] 프로필에 저장2. Sign in — writes the [saml] profile to ~/.aws/credentials
samlgate login

# 3. 사용3. Use it
aws sts get-caller-identity --profile saml
samlgate status

Microsoft Entra ID에서는 엔터프라이즈 애플리케이션 → AWS 앱 → 속성 → 사용자 액세스 URL이 로그인 URL입니다. 첫 로그인에서 "로그인 상태를 유지하시겠습니까?"에 예를 누르면 다음 갱신 때 세션을 다시 쓸 수 있습니다. In Microsoft Entra ID the sign-in URL is Enterprise applications → your AWS app → Properties → User access URL. Answer Yes to "Stay signed in?" on the first sign-in so later renewals can reuse the session.

03

동작 방식How it works

SAML에는 localhost 콜백이 없습니다. 로그인 뒤 IdP는 브라우저가 SAMLResponse를 AWS 엔드포인트로 POST하게 하는데, samlgate가 그 요청을 가로챕니다. SAML has no localhost callback. After sign-in the IdP makes the browser POST the SAMLResponse to a fixed AWS endpoint — samlgate intercepts exactly that request.

  1. 전용 프로필로 Edge/Chrome을 엽니다.Opens Edge/Chrome on a dedicated profile.
  2. AWS로 가는 SAML POST를 가로챕니다. 이 요청은 AWS에 도달하지 않습니다.Intercepts the SAML POST to AWS — it never reaches AWS.
  3. 로컬 완료 페이지로 응답하고 브라우저를 닫습니다.Answers with a local "you can close this window" page and closes the browser.
  4. STS AssumeRoleWithSAML을 호출해 프로필에 씁니다.Calls STS AssumeRoleWithSAML and writes the profile.

saml2aws 그대로saml2aws-compatible

~/.saml2aws 설정을 읽고, 같은 형식으로 자격 증명을 씁니다. saml2aws login -a work 대신 samlgate login -a work.Reads ~/.saml2aws and writes credentials in the same format. Replace saml2aws login -a work with samlgate login -a work.

MFA·조건부 액세스 그대로Real browser, real MFA

터미널에 비밀번호를 입력하지 않습니다. 실제 브라우저에서 IdP가 요구하는 MFA와 정책을 그대로 거칩니다.No password prompt in the terminal. Your IdP's MFA and Conditional Access run in a real browser.

가벼운 단일 실행 파일One small native binary

런타임, Playwright, 브라우저 드라이버를 내려받지 않습니다. 텔레메트리도 없습니다.No runtime, no Playwright, no browser-driver downloads. No telemetry.
